# 服装、动作、表情统一方案

日期：2026-11-26。适用：二维动漫/插画角色，可穿旗袍、和服、道袍等；不要求音素级嘴型；用户电脑不能依赖大型视频推理；优先复用开源组件。本文件是收敛后的工程方案，实际生成效果尚需目标素材验收，不覆盖既有代码或宣称已完成全流程。

## 问题定位

当前衣料多边形遮罩内纹理流动只能制造局部视觉变化，不能模拟不同衣物结构。它既不表示身体与服装的遮挡关系，也没有袖口、腰带、开衩、宽袖等约束，因此不宜继续发展为通用服装动画技术。

语义识别、像素分割、衣物运动是三件事：识别给出衣物类别/结构；分割给出可见区域；运动还需要材质、锚点、遮挡和未见区域信息。单图通常不能可靠恢复全部物理信息。不要对所有分割出的衣服应用同一种正弦摆动，也不要将其称为通用布料物理。

## 主路线：生成端制作完整动态人物，播出端不再二次扭曲

### 1. 输入分析与标准角色

使用视觉理解服务分析服装结构、贴身/宽松、宽袖、长下摆、腰带、开衩、飘带、头发、手臂遮挡，输出可编辑的制作说明；保留角色身份和装饰特征，经已有图片服务得到统一正面构图。

识别结果用来选择参考表演、动作幅度与生成约束，不用来在低配客户机运行重型服装分割/物理。

需要精准保护区域、前景提取或审核时，再引入[Grounded-SAM-2](https://github.com/IDEA-Research/Grounded-SAM-2)和[SAM 2](https://github.com/facebookresearch/sam2)的现有实现。前者提供文本定位＋分割，后者提供图像/视频掩码跟踪。它们不是专门保证二次元旗袍/和服/道袍识别的模型，需检查掩码；不作为每个生成任务的强制步骤。

### 2. 动作、衣服、表情共同生成

制作端主候选：[Wan-Animate](https://humanaigc.github.io/wan-animate/)，优先通过官方开源流程或合适的托管服务使用。官方实现以身体骨架和面部信号分别驱动，生成完整画面；不只转动剪下来的手臂。

使用已制作的参考表演库：待机、讲解、开心、思考、招手、介绍、点头/小幅鞠躬。角色图提供外观，参考表演约束动作和表情节奏。服装运动由视频生成模型形成；这不是可验证布料物理，也不保证每种衣物一次成功。

衣物不同，目标也不同：

- 旗袍：衣身随呼吸/姿态轻微变化，开衩与衣摆适度运动，保持腿与布料关系；不应像宽裙一样大幅飘动。
- 和服：宽袖随手臂动作滞后摆动，腰带区域稳定，衣身重量感与袖口轮廓保持。
- 道袍/长袍：衣襟、袖口、下摆与飘带协调运动，腰部束缚位置稳定，避免与腿一同拉长。
- 头发、饰品同样属于完整画面运动，需要检查边缘、遮挡和人物一致性。

### 3. 标准素材包

复用FFmpeg/ffprobe处理视频编码、尺寸、帧率、裁剪和音轨。优先使用独立背景与人物前景，以防不同片段的背景跳动；生成若使用固定整幅背景，必须先验证其稳定性。

视频抠像可考察已有工具，但不直接把任何分割掩码当成高质量透明边缘。绿色服装不适合统一绿幕；二次元宽袖、发丝、飘带的透明边缘要单独检查。MatAnyone提供现成人像视频抠像，但其许可证是NTU S-Lab License 1.0，不能按MIT组件直接打包商用；SAM 2掩码也不等于alpha matting。

首轮成品角色包至少覆盖：自然待机、平静说话、开心说话、思考/疑惑说话、招手、答谢、介绍。通用嘴型已包含在整个人物视频中，不再额外贴嘴。

这些是可复用语义状态，不要求生成“所有表情×所有动作”的笛卡尔积；但纯视频无法在缺少对应素材时自由组合。新增情绪需要增加相应素材，属于内容制作，而不是偷偷承诺视频可任意重定向。

### 4. 播出优先复用OBS媒体能力

首个真实效果验证直接采用现有OBS媒体源与过渡，通过[obs-websocket](https://github.com/obsproject/obs-websocket)接现有客户端，不再先写一套媒体引擎。

本次核对协议确认提供：

- `SetCurrentProgramScene`：切换播出场景。
- `SetCurrentSceneTransition` / `SetCurrentSceneTransitionDuration`：选择过渡和时长。
- `TriggerMediaInputAction`：播放、停止、重播等媒体控制。
- `GetMediaInputStatus` / `MediaInputPlaybackEnded`：查询和接收播放结束。
- `SetInputSettings`：更新媒体源设置。

OBS负责既有解码、循环、淡化和输出；当前Electron/FastAPI负责素材管理、已审核文本、语音、礼物与动作队列。OBS作为独立程序接口连接，避免复制其代码再维护一套。OBS版本、WebSocket鉴权与各平台行为在验证时固定。

表情/动作切换只能在共同姿态或许可窗口发生；预加载与短淡化只缓解小差异，不能保证任意两段AI视频无缝。不同片段从同一标准参考、同类表演和自然回位处制作，未达标则重做素材，而不是继续加网格变形遮掩。

已有透明播出窗口和旧ActionPlayer保留以防破坏现有工作，停止扩大；是否还需要嵌入式播出预览，在OBS链路证明效果后单独评估，不将自建渲染器当作最终方案前提。

### 5. 保留商品和实时互动业务

继续使用当前知识库、屏蔽规则、输出校验、礼物模板、TTS缓存与事件队列。由审核后的回复/业务意图选择素材，而不是让未经审核的弹幕直接控制表情。

语音可与已有说话/带轻微手势视频同时播放；闭嘴鞠躬则按语句边界安排。短暂停顿保持说话状态，避免反复切场。礼物优先、过期、去重、停止和恢复都需要在实际OBS控制链中验证。

## 其他候选定位

- **EasyAIVtuber/THA3**：有现成嘴部、眨眼、头部、轻微身体动作及参数过渡，值得用作对照；不等于有宽袖、长袍的独立自然运动，不作为完整服装路线的保证。
- **DH_live mini**：已有低配视频数字人运行栈，可用于评估后续脸部处理；本方案不要求精确口型，因此不必为此额外添加它的预处理和WASM依赖。
- **LiveTalking**：可借鉴动作/音频编排，其正常说话分支仍有模型推理，不作为普通客户电脑的默认依赖。

## 先验证再进入正式改造

使用至少三种实际角色：贴身旗袍、宽袖和服、长道袍。每个至少验证：

1. 待机/说话时，衣物有符合结构的变化；装饰与腰带稳定，裸露肢体不被衣物拖动。
2. 招手或介绍时，袖子与手臂运动协调，没有穿帮和明显变形；答谢动作后回位。
3. 开心/疑惑表情确实可见；嘴动即可，不要求逐字口型，脸部身份不漂移。
4. 待机→说话→动作→说话→待机连续播放，循环和切场不出现明显跳变；评估允许等待的切换窗口。
5. 真正使用OBS媒体源和WebSocket控制，验证配音、礼物插播、停止、重连和后续恢复。
6. 普通电脑实测，不把作者CPU或显卡数字当成整套系统最低配置；记录生成可用率和每条合格素材成本。

通过这些实样后才将该组合定为正式路线。云视频生成仍有质量随机性；若这组实样不通过，则应明确说明成本/质量不满足，而不是宣称已经找到保证任意衣物自然运动的技术。

## 本轮依据

- Wan-Animate官方项目页与预处理指南：全身动作/表情信号及重定向限制。
- Grounded-SAM-2与SAM 2官方README：定位、掩码和视频跟踪，不是衣物动力学。
- obs-websocket生成协议：确认已有媒体控制、播放结束与场景过渡接口。
- EasyAIVtuber动作调度代码与DH_live mini部署文档：区分轻量脸部驱动、身体/衣物动作生成和媒体播放。

本轮未改正式播放器，未执行收费生成，没有以文档调查代替三类服装的实样验收。
