# 二维虚拟主播：运行成本与技术路线复核

核对日期：2026-11-26。适用范围：自定义桌面客户端、用户上传二维角色图、商品知识问答、语音播报、礼物答谢、普通电脑运行；当前接受“实时说话＋语句间预制动作”，暂不考虑3D。

本次核对了项目当前实现、候选项目的官方README/API/许可证或产品商店，以及阿里云官方价格。没有下载运行新的推理模型，没有调用收费生成接口。下述硬件与性能引用属于作者公布数据；本次没有对候选引擎做同图效果或低配机器实测。

## 推荐结论

当前约束下，最值得优先验证的成本结构是：**保留现有商品和事件业务层，本地轻量渲染与视频播放，云端一次性制作动作库，本地或低价云TTS，小模型仅处理需要归纳的商品回答。**

这不是已经测出“全市场最低成本”的结论。主要原因是：角色和动作素材可反复使用，播出时不需要视频生成GPU，也不需要按每秒画面持续向服务商付费。实际成片性价比仍取决于生成后的可用率。

若用户允许从高质量成品角色模板开始，另一条成熟路线是专业制作的Live2D模型＋成熟播放器。它的模型制作成本较高，但长期运行成本低、动作可控。若坚持任意上传图片自动定制，目前没有从本次查阅资料中确认一个低配、低价、全自动且质量稳定的完整开源产品。

| [MatesX](https://github.com/kleinlee/MatesX) | 多端轻量数字人应用外壳 | README明确不提供底层算法实现，自定义形象需要其平台/API。不是可完全自主替代的开源角色生成引擎 |

| [AI-Vtuber](https://github.com/Ikaros-521/AI-Vtuber) | 多直播平台、循环文案、TTS和角色引擎编排 | 参考事件编排；不替代角色制作。当前仓库标GPL-3.0，README另写商业使用需联系授权并提到抽成，不能按“免费闭源底座”预算 |
| [Wan2.2开源模型](https://github.com/Wan-Video/Wan2.2) | 图生视频、音频驱动视频、参考视频动作迁移 | 可在制作端研究；不打包给普通直播用户。开源模型与云端同名近似型号不能直接等同 |

关于“能运行”和“实时”：MuseTalk当前README列出一项Windows测试：RTX3050Ti笔记本4GB显存、FP16，生成8秒视频约需5分钟；同时也公布V100等设备的实时结果。这说明显存能装下模型，不等于在目标低配电脑上能实时直播。LiveTalking的GPU FPS也不能替代整条语音链路延迟。

VTube Studio商店公布的单应用最低配置为4GB内存、2GB独显，推荐6GB内存、4GB独显；这些数字不包含同时运行OBS、其他业务软件，也不保证任意复杂Live2D模型都达到预期帧率。

## 生成端与播出端的组合

### 生成端：为一个角色一次性制作素材

1. 沿用已有图片服务，制作标准正面角色、说话/闭眼等一致性素材。
2. 准备固定镜头的招手、点头/鞠躬、介绍手势参考视频，首尾回到相同姿态。
3. **优先比较万相图生动作标准版与低价首尾帧版。** 图生动作依靠参考视频控制动作；首尾帧版依靠图像和提示词控制。两者均需筛选，均不保证自动生成合格动作。
4. 保存合格短片，生成后通过当前客户端预览、启用；不在日常直播中反复生成相同素材。

本次查到的北京地域官方价格：

| 方式 | 单价 | 按5秒输出计算 |
| --- | --- | --- |
| wan2.2-kf2v-flash，480P | 0.10元/秒 | 0.50元 |
| wan2.2-kf2v-flash，720P | 0.20元/秒 | 1元 |
| wan2.2-animate-move，标准模式 | 0.40元/秒 | 2元 |
| wan2.2-animate-move，专业模式 | 0.60元/秒 | 3元 |
| wan2.2-s2v，480P | 0.50元/秒 | 2.50元 |
| wan2.2-s2v，720P | 0.90元/秒 | 4.50元 |

统一按5秒算账是为了比较，不代表所有接口只支持5秒。输出规格以所选模型为准。请求成功但效果不满意的样片仍可能计费；失败请求的处理以供应商规则为准。

示例测试预算：3个动作，每种方案每个动作生成2次，首尾帧720P为6元，图生动作标准版为12元，共18元；这只是12条样片的预算，不承诺一定取得3条合格素材，也未授权或执行这些调用。

比较标准应是“每条合格素材的成本”，即平均单次费用除以可用率。没有同图测试的可用率数据，就不能只凭单价宣布某个服务最终最便宜。

### 播出端：尽量避免连续图像推理

- 保留现有Electron客户端、知识库、内容过滤、队列与OBS输出。
- 待机/说话使用轻量实时渲染，语句间播放预制动作。改善口型时，优先评估有限的整脸/整体表情状态及更可靠的时间对齐，不再叠加脱离角色的独立嘴图。
- Windows系统语音可作为免费离线兜底；需要更好的普通话时，先比较轻量CPU TTS与低价云TTS的声音、首句延迟和部署复杂度。
- [sherpa-onnx的Kokoro模型](https://k2-fsa.github.io/sherpa/onnx/tts/pretrained_models/kokoro.html)明确提供中英多语言及INT8模型，是可做小样验证的本地候选。代码、音色和模型分别核对许可；不能只看运行库许可证。
- 以官方北京地域当前价格为例，qwen3-tts-flash为0.8元/万输入字符；1万新字符配音约0.8元。固定讲稿缓存后只需合成一次，个性化昵称等变化文本则计入新合成。
- 常见商品FAQ可以优先从已核对知识条目直接回答，需要归纳时再调用云端小模型；不必为每条事件调用大模型。内容过滤和最终输出核对仍保留。

完整成本应拆为：角色制作与返工＋新文本的LLM/TTS调用＋本地运行/维护费用。不能把“每小时播放”直接等同于“每小时都生成新视频”。

## 不适合当前默认路线的方案

- 每条弹幕都调用云数字人生成完整口播视频：增加等待和按秒计费。万相数字人720P每分钟新生成视频为54元，不适合作为低价长时互动的默认链路。固定宣传视频可以单独使用。
- 在每个客户电脑上部署Wan、MuseTalk等大型视频推理：部署、显卡、驱动、速度和维护成本都转移给用户。
- 继续仅靠固定多边形切图后转动肩肘：成本低，但已经在当前素材上暴露质量问题。换绑定引擎并不能自动补齐遮挡素材或动作设计。
- 直接以开源整合项目替换全部业务：商品约束、素材生成和动作质量通常仍要另做，同时增加迁移成本。

## 下一步最有价值的验证

1. 用同一个用户角色，完成首尾帧版与图生动作版的招手、答谢、介绍样片对照。检查身份一致、手指、裙摆、背景及首尾回位。
2. 在同一段真实中文配音上比较当前口型与DH_live mini的小样。只有确认支持该插画且可独立制作/分发素材后，才考虑替换播放器。
3. 用一套合格成品Live2D模型在VTube Studio中播放相同语音与动作，作为质量参照。若它明显更好且目标用户接受模板，应提供模板入口。
4. 在实际低配电脑上测720P、30FPS目标、声音延迟、内存与持续播出稳定性。8GB内存＋核显可以作为待验收目标，不是本次已验证的最低配置。

当前项目已经有素材状态与短片播放的基础，但现有真实AI动作质量、普通低配机器性能、抖音采集连接还没有在这次调研中得到端到端验证。应先完成这些效果和运行验证，再扩大模型种类。
