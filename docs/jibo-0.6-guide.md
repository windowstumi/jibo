# 极播0.6 / 0.6.2：角色卡与制作预览

日期：2026-11-26。此说明优先于0.5历史记录。角色卡播放与旧版场景并存；本次没有调用收费生成接口。已有目标角色视频可直接本地整理，不必再次点击云端「生成完整角色」。

## 0.6.2移除旧点头

已删除旧场景渲染器的礼物／答谢网格点头，包括头部附加角度、身体偏移、事件手势参数和旧预览按钮。旧场景不再显示或排队旧答谢动作，礼物不再自动读取旧场景的答谢短片；仅保留语音答谢。视频角色卡收到礼物时播放本卡的`thanks.webm`或`thanks.mp4`，不会调用旧点头。自然待机、呼吸、眨眼和已生成视频不受影响。

回归检查包含真实角色的旧渲染器像素比较（历史gift/thanks参数不产生附加变形），以及互动实验室点击发送礼物后的实际答谢视频路径、解码进度和旧画布隐藏状态。旧项目素材文件保留用于迁移，不删除用户原文件。

## 0.6.1工作台动作修复

工作台会明确显示“视频角色卡”与“旧场景”。仍在旧场景时，点击“选择本次生成的视频角色”，再点击“预览并应用此视频角色”；确认应用后自动返回工作台。新动作按钮与卡内视频一致，并显示当前实际播放的视频状态。未开始彩排时可以直接预览；开始后，点头答谢、微笑招手和介绍手势进入动作队列，礼物自动触发点头答谢。旧网格动作仅在明确选择旧场景时使用。

角色卡排队动作不再访问遗留旧场景目录，避免迁移后旧目录不存在导致视频动作失败。回归使用同一份真实角色视频，检查每个工作台动作的视频源与播放时间推进，分别验证手动答谢、招手、介绍和礼物自动答谢。

## 当前角色的操作步骤

1. 关闭旧客户端，将`Jibo-Studio-0.6.2-win-x64.exe`与原有`YingboData`放在同一个可写目录，打开新版。
2. 进入「角色制作」，选择「我的极播主播」。当前机器已准备好这张角色卡，尚未替用户确认验收或应用。
3. 点击待机、平静说话、点头答谢、介绍手势、微笑招手，检查预览。开心说话未配置时使用平静说话。
4. 在配音测试中输入文字、选择动作并试听。语音使用「接入设置」中的TTS；Windows系统TTS可本地运行，选择云TTS时按该服务计费。
5. 点击背景开关检查透明人物与独立背景。勾选验收确认，点击「应用到直播工作台」。背景开关状态随应用保存。
6. 回到直播工作台，角色选择器会选中新卡。选择商品，开始彩排，测试商品问答、过滤语句、礼物答谢。切换角色会停止原播出，需重新开始彩排。

应用只切换本地播出角色，不调用图片或视频服务，不会启动平台推流。可以在工作台继续使用旧场景。

## 创建其他角色卡

角色卡包含标准透明人物图、五项基础动作、可选情绪、独立背景、名称及显示偏好。它不包含商品、API密钥或机器上的音色配置。

- 已有当前角色的五段成品绿幕视频：在配置中上传，选择已分离的正面人物场景，然后点击「使用现有视频创建角色卡」。后台用FFmpeg去绿、生成透明WebM、保存为独立卡；本地整理失败可继续，不产生生成费。请勿把其他演员的参考表演当作本角色成品使用，此入口不会进行人物替换。
- 收到已有角色卡：点击「导入角色卡」，选择ZIP，预览、确认并应用。导入分配新ID，不覆盖原卡，需重新验收。
- 从图片制作新角色：展开高级云端制作入口，配置GPT视觉、图片服务、万相及有权使用的参考表演，核对费用再提交。该入口仍会产生服务费用，不自动付费重试。

本地整理需安装FFmpeg及ffprobe并加入PATH后重启客户端；角色卡导入需要ffprobe检查视频。发布EXE未附带这两个工具。已经整理好的卡在本机播放由内置Chromium解码，不需要运行视频生成模型、Python开发环境或CUDA。

新云端任务也会在下载成品后本地转成透明WebM。此转码已用当前真实绿幕视频验证，但本次未重新付费跑完新角色云端链路。绿色服装、复杂透明材质、非纯绿背景可能被误抠，必须用目标素材检查。

## 切换、导出与迁移

- 在角色卡列表点击卡片可预览，点击应用可切换。卡名可修改，修改后保存。
- 「导出角色卡」导出独立ZIP：标准图、视频、可选背景及清单，不包含原始参考文件、服务密钥或公网素材链接。另一台机器导入后重新验收。
- 「导出迁移项目」还会携带商品、规则和答谢模板，以及当前应用角色卡；另一台机器导入后配置自己的TTS和服务密钥，再确认应用角色。角色卡上限300MB，完整项目上限100MB；角色过大时请单独导出卡或复制完整数据目录。
- 要保留所有角色和全部本机配置，先退出客户端，再复制EXE和整个`JiboData`或沿用的`YingboData`。完整数据目录含本机密钥，请仅迁移到可信设备。

跨Windows/macOS/Linux迁移使用角色或项目ZIP，目标系统须有对应构建和可用TTS。Windows EXE不能直接在其他系统执行。本轮只实测Windows x64；macOS/Linux保留构建流程，未声称已在这些系统验收。

## 播出与声音

制作页的预览、配音测试已迁到角色制作中。工作台和透明播出窗口使用同一角色卡与现有语音队列，保留商品讲解、内容过滤、礼物优先。声音由实际音频开始/结束推进状态；答谢动作结束后仍有语音则回到平静说话，无语音则回待机。

最多两个原生视频槽，切换使用约250ms交叉淡化。待机与说话保留源视频中的呼吸、眨眼、头发和服装运动，不增加旧网格形变。没有独立嘴贴图，也没有音素级对口型；说话视频自身需要有嘴部活动，当前素材未出现的表情不会凭空生成。

「打开播出窗口」或复制OBS浏览器源地址，可显示透明角色；透明播出画面优先接管语音，工作台预览停止发声。制作页的单独配音测试请在彩排前进行，避免与正在播出的声音重叠。

外部OBS WebSocket控制保留在可选折叠区，不是客户端内预览的必需依赖。本次验证了独立透明播出页面接管声音，未在实际OBS Studio和抖音中完成现场推流验收。

## 验证与限制

已用当前角色的五段真实成片测试透明WebM解码、动作切换、Windows实际TTS、预览背景、验收应用、ZIP导出导入、改名与切换、工作台实际使用切换后的ID、模拟礼物及透明播出声音接管；并保留旧版场景回归。自动测试使用临时数据，不改动用户正在使用的角色配置。

淡化不能保证任意两段视频首尾姿态无缝，也不能修复原素材中的肢体错误、变脸、说话嘴部不足或循环接缝。请在制作预览中验收当前素材的观感；若不合格，需更换对应视频。本轮不自动重新生成或扣费。

## 实现与复用位置

| 能力 | 复用入口 |
| --- | --- |
| 动作播放、循环和过渡 | Chromium `HTMLVideoElement`、Web Animations；`static/character-player.js`只负责状态编排，最多两个视频槽 |
| 透明视频 | FFmpeg `chromakey`、`despill`、VP9 alpha；`character_pipeline.transparent_video`使用独立进程，非本地AI推理 |
| 卡片和迁移 | Python标准库ZIP/JSON/文件接口、Pillow、现有ffprobe；`character_cards.py` |
| 语音与直播业务 | 原有`/api/scenes/test-voice`、`/api/player/tick`及商品/过滤/优先队列；`static/stage.js`接入原播放器生命周期 |
| 可选外部OBS | 原有OBS Studio原生媒体源与`obs-websocket-js`；`desktop/obs-client.cjs`现支持WebM |

没有打包FFmpeg、OBS或视频生成模型。FFmpeg按发行构建可能采用LGPL或GPL；OBS是独立GPL程序，obs-websocket-js按MIT许可使用。若后续捆绑媒体工具，需单独核对所选二进制的许可与再分发义务。

原生播放API参考：[HTMLVideoElement](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement)、[Web Animations](https://developer.mozilla.org/en-US/docs/Web/API/Element/animate)；媒体滤镜参考：[FFmpeg Filters](https://ffmpeg.org/ffmpeg-filters.html#chromakey)。
