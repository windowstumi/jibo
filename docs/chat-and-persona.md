# 极播0.8.3：聊天与角色设定

在「互动守则」勾选「允许聊天（调用云端大模型）」并保存。默认关闭，旧配置自动保持关闭。关闭时继续使用商品知识库问答、基础身份介绍和招呼；开启时可回应商品之外的日常话题，需要配置兼容Chat Completions与JSON输出的大模型。网络复用现有代理客户端，读取Windows系统HTTP代理，本地模型接口直连；不会代为开关VPN。

在「角色制作」选择角色卡，填写「角色设定」，保存名称与设定。可写性格、背景、兴趣和说话风格，最多2000字；应用角色时一并保存并同步工作台。设定随角色ZIP和项目中的角色ZIP迁移，旧角色包没有该字段时按空设定兼容。角色包不携带云端密钥，也不能通过导入角色包打开聊天或修改本机互动守则。角色设定不要包含私密资料；使用聊天时，它会发送至所配置的云端模型。

## 处理流程与费用

输入先经过启用的屏蔽词及内置越权指令筛查，再按当前角色资料与检索结果请求模型生成结构化候选。商品事实仍须引用知识库证据，并校验数字；不能通过将商品问句标为闲聊来绕过这一要求。候选还必须经过第二次、无对话历史的审查请求，审查通过后才合成语音。正常云端回复通常两次模型请求；本地筛查拒绝时不请求模型，生成步骤已拒绝时不再审查。费用和延迟由所选模型决定，没有自动付费重试。

审查超时、连接失败、格式异常、证据无效或审查拒绝时，跳过本次互动并在记录中显示原因，不直接播出未审查候选。两次请求使用同一配置模型的不同独立请求，并非两种不同模型。当前不保存或向模型提供多轮观众聊天历史，不支持调用工具、联网检索、读取本机文件或访问配置密钥。

关闭聊天、修改当前角色设定或调整互动守则后，已生成但未播出的旧聊天作废；正在播出的旧聊天在播放器下一次同步时取消。当前是单次语音与非流式生成，不能保证设置修改与扬声器停止之间零延迟。

## 防诱导边界

- 角色设定、商品证据和弹幕均放在结构化资料中，不能获得修改系统约束的权限；角色设定本身命中禁言或越权筛查时要求修改。
- 本地检查涵盖NFKC、标点和零宽字符规范化，以及有长度/层数限制的Base64、URL编码、HTML实体和Unicode转义内容。内置常见中英文越权指令筛查独立于可编辑屏蔽词。
- 模型生成与独立复核需识别假冒管理员、规则改写、角色扮演、谐音/拼音等变相输出；模型没有工具与密钥上下文。回复在生成、合成后和待播时继续进行规则/策略检查。
- 这些措施不能保证100%防住提示词攻击。相同模型的两次检查也可能出现相关性失误；词表和编码筛查不能覆盖所有语言、隐写与改写方式。重要禁言要求应补入互动守则，并用实际模型持续验收；严格商品模式可随时关闭聊天。

## 复用与选型

运行时复用现有`app.llm_json`兼容接口、`image_service.image_client`系统代理处理、商品检索及统一语音队列，不新增本地GPU模型或代理框架。新增的`interaction.answer_chat`只负责生成/复核调用、结构校验与现有业务接线。

核对了[LLM Guard的PromptInjection实现](https://github.com/protectai/llm-guard/blob/main/llm_guard/input_scanners/prompt_injection.py)：它通过Transformers/ONNX加载额外的分类模型，部分小模型还需授权访问；目前没有完成本项目中文观众弹幕、低配客户端和分发模型条件的验收，因此列为需适配候选，没有将其称为已接入能力。

当前分层方案参考[OWASP提示注入防护清单](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)中的结构隔离、输入筛查、输出检查与模型复核。未引入或复制LLM Guard代码/权重，不新增其运行时依赖。
