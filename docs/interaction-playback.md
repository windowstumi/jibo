# 极播0.8.4：互动预览与播出一致性

## 使用

工作台选择已验收的角色卡，在「互动实验室」发送弹幕或礼物。未播出时，客户端自动启动「仅互动预览」，不生成或循环播放商品讲解。普通聊天是否允许仍由「互动守则」开关决定。互动通过审核和语音合成后，字幕、语音与动画一起进入预览；点击停止可结束。

已经开始商品彩排时，实验室发送的互动沿用正在播出的队列，不切断当前语句。平台`/api/events`接入不会擅自启动播出，仍需操作者先开始彩排或互动模式。

此前本机诊断到runtime.active=false、current=null、queue_length=2，两条回复状态ready；不是模型没有回答，而是没有启动播放器消费队列。0.8.4补齐实验室发送时的启动操作。

## 动画与语气

云端聊天仍使用原来的生成和审查两次请求，不额外调用情绪模型。审查步骤根据最终回复的语义返回neutral/happy/curious/sad/serious，以及none/greeting/thanks/present动作；服务器只接受这些枚举，不允许模型提供文件名、路径或任意动作。低于互动守则的资料及观众要求不能授予动作权限。

- 招呼/自我介绍：招手；感谢：答谢；商品介绍：介绍手势；普通回答：说话。
- 开心：配置了开心说话时使用该视频，否则沿用现有播放器回退平静说话。手势结束后，语音仍在播放时回到本条回复的说话状态。
- 疑惑、难过、严肃：当前没有对应视频槽，使用平静说话，不套用开心招手或答谢。礼物固定答谢。
- 未开启聊天及固定模板，使用本地的简短语义规则，不另付费请求分类。

语气标签用于现有视频选择，不会凭空生成新的表情。当前GPT-SoVITS等语音适配没有情绪控制参数，这次没有将声学情绪或音素级嘴型精确同步作为已实现能力；嘴部活动仍来自完整人物视频。

## 时间与取消

每条播出任务包含自己的文字、音频、语气和手势。使用原生HTMLMediaElement准备音频后再开始动作与声音，字幕在audio.play成功后显示。视频仍沿用原播放器的约250ms交叉淡化，不增加嘴贴图或新动画引擎。

声音结束后先隐藏字幕；如果手势尚未结束，保持当前任务直到手势自然结束并淡回待机，才让下一条回复开始。手势先结束而声音仍在播放时，回到本条回复的说话循环。停止/规则取消、任务替换和角色切换会作废旧异步回调，避免旧字幕或声音重新出现。服务器取消当前任务且没有新任务时，画面端也停止旧声音。

`/api/studio/start`支持`interactions_only:true`；此时商品可不填，仍要求有效的已验收角色卡。普通商品彩排维持原商品校验。

## 验证

2026-11-27使用当前蓝发女仆角色卡、配置的真实云端模型以及本机雷电参考音色执行桌面端到端测试：

- 从停止状态通过实验室表单自动开启互动模式；真实回复判定happy/greeting，实际播放greeting视频；字幕等于任务文字，实际音频地址属于同一任务。
- 真实回复音频17.7秒；礼物测试使用简短模板，音频1.22秒；音频结束后字幕隐藏，答谢视频仍属于原任务，后续平静回复等待动作结束后才开始。
- 后续知识库回复实际使用talk，旧答谢没有串入；最后回idle，没有自动播放商品讲解。

结果与实际WAV在忽略的`test-output/interaction-live`。测试使用隔离的角色副本和临时配置数据库，结束后删除包含密钥的临时数据库，未改用户原配置/原角色卡。不会自动重复付费请求。

76项Python、16项Node回归通过；打包目录版实际角色的配音、视频动作、礼物答谢、角色迁移及透明播出回归通过（临时报告目录`yingbo-smoke-dvjqW2`）。已生成0.8.4 Windows便携EXE，原本已安装的语音组件无需重装。

开发者显式验收脚本（会调用所配置的真实云端模型；每次选用新的结果目录，需原客户端本地音色已加载且未在直播）：

```powershell
.\.venv\Scripts\python.exe scripts/smoke_interaction.py --data E:\waibao\release\YingboData --report-dir test-output\interaction-new-run
```

可用`--target release\Jibo-Studio-0.8.4-win-x64.exe`测试新打包客户端。脚本复用项目已有GPT-SoVITS桥接器和当前安装的真实推理服务，不训练模型、不创建视频夹具。模型自身仍有判断误差，未覆盖的情绪需未来提供匹配视频再验收。OBS外部原生场景路径同步接收动作和说话情绪，但本次未连接真实OBS现场验收。
