# 极播 · 虚拟人直播客户端

使用 Electron + Python/FastAPI + SQLite 的本地桌面客户端。当前版本 **0.7.0**。

## 0.7.0 项目内本地克隆语音

接入设置 → 语音合成 →「本地克隆音色 · NVIDIA」可安装并启用本地语音。客户端自动下载独立Python、锁定的CUDA/PyTorch依赖和公共模型，打开客户端时显示加载与预热进度；不再要求客户单独运行GPT-SoVITS或填写端口。支持试听、语速、下载源、自动加载和独立音色包导入，退出客户端会关闭自己启动的语音进程。

当前组件仅支持Windows x64与NVIDIA，采用GPT-SoVITS v2推理；GPU驱动由目标机器提供。默认音色由用户声明授权商业分发，代码与第三方说明随包保留。主包不包含GPU环境和公共大模型，首次启用需要数GB下载及至少15GB可用空间。使用方法、音色包格式、默认音色构建输入和测试边界见 [本地语音组件](docs/local-tts-component.md)。

0.6.2删除旧版程序化点头的着色器位移、事件驱动与旧答谢入口，并禁止礼物回退到旧场景答谢短片。旧场景收到礼物只做语音答谢；视频角色卡只播放自身的答谢视频。

0.6.1修复工作台仍使用旧动作的入口混淆：明确显示当前是视频角色卡还是旧场景，直接列出本卡的自然待机、平静说话、点头答谢、微笑招手、介绍手势；开播前可点视频预览，彩排期间手势按队列播出。待验收卡也可从工作台选中，再进入预览应用；应用后自动回到工作台。角色卡动作不再读取遗留旧场景目录。

## 0.6.0 角色卡、制作预览与工作台同步

「角色制作」新增角色卡列表和集成预览，可检查待机、说话、答谢、介绍、招手，输入文字试听真实TTS，切换独立背景。复用已有语音队列和Chromium原生视频播放，不叠加独立嘴贴图。确认并应用角色后，直播工作台同步选中新角色；切换会停止原角色播出，再开始彩排。

已有本角色成品绿幕视频时，点击「使用现有视频创建角色卡」进行本地去绿、透明WebM整理，不调用收费生成接口。云端重新制作保留在折叠的高级入口。角色卡可改名、切换、独立ZIP导入导出；导入后需要在本机预览确认。项目迁移包也会携带当前应用的角色卡，密钥不进入包。

已用当前目标角色的五段真实视频、Windows实际语音，在开发版与打包版执行界面回归。原素材中的动作、嘴部活动及循环接缝仍需人工验收；250ms淡化过渡不能修复原视频姿态差异。说明和迁移步骤见 **[极播0.6使用说明](docs/jibo-0.6-guide.md)**。下方0.5及更早章节为历史记录，新版行为以0.6说明为准。

## 0.4.0 实时说话＋预制动作短片

待机和说话仍保留原来的呼吸、头部轻晃、眨眼、衣料风动与动态背景。招手、介绍、答谢可使用本地短片，在语句之间静音播放；不会把口型叠加到动作视频上。礼物答谢先播放已启用的答谢动作，再开始语音；没有合格短片时直接语音答谢。

1. 形象工坊载入一个场景，在「预制动作短片」下载标准参考图、复制视频生成提示词。
2. 使用外部图生视频工具制作动作：固定镜头，首尾与参考图的姿态、比例、位置一致，各保持约0.5秒，闭嘴完成一个动作再回位。这里没有自动调用视频生成服务，也不产生新的视频服务费用。
3. 导入1–8秒、20MB以内的绿幕MP4/WebM或透明WebM，宽高比与参考图一致。尺寸不超过2048边长及250万像素。建议24/30 FPS、720p以内起步；更低配置应先实测解码负载。
4. 导入检查首尾轮廓和颜色差异。点击「预览完整切换」，完整播放成功后，再人工确认并启用。淡入淡出无法修复视频内部的变脸、肢体错误或明显的首尾姿态差异。
5. 工作台招手/介绍/答谢按钮会排队到当前语句后播放。收到合规礼物会自动选用答谢短片；内容过滤、礼物优先和单播放器声音归属继续生效。

过渡顺序：400ms逐步收回实时形变 → 400ms淡入短片首帧 → 播放短片 → 400ms从末帧淡回角色 → 400ms恢复实时形变 → 开始下一句。实时动画时钟不重置，独立背景持续运动。短片预加载/解码失败或超时会跳过，停止播出和OBS接管会取消旧播放序列，防止过时语音突然播放。

动作与场景随迁移项目一起导出，项目包上限提高到100MB。导入另一项目后动作需要重新预览启用；标准角色图发生变化时，旧动作自动停用。动作播放器使用Chromium/WebGL，不增加PyTorch或本地视频生成模型依赖。未配备实际动作视频时，可使用 `YINGBO_SMOKE_CLIP` 指定与场景匹配的测试短片执行桌面回归；测试夹具仅验证解码、过渡和队列，不代表AI动作质量。

## 快速开始：全新克隆

**Windows 10/11 x64：首次联网后运行一条命令即可。无需预装 Python、Node.js、npm 或 Java。** 脚本将固定版本的 Node.js、uv、Python 下载到项目的 `.runtime/`，在项目内创建 `.venv/` 和 `node_modules/`。不修改系统 PATH，不依赖开发者电脑上的其他目录。

Windows PowerShell：

```powershell
git clone https://github.com/windowstumi/jibo.git
cd jibo
.\start.cmd
```

也可以在资源管理器双击 `start.cmd`。单独安装环境或检查：

```powershell
.\setup.cmd          # 仅准备项目内环境
.\check.cmd          # 环境、Python/Node 测试、桌面启动检查
```

Windows 打包：

```powershell
.\build.cmd
.\build.cmd -Target directory
```

输出为 `release/Jibo-Studio-0.7.0-win-x64.exe`。目录版位于 `release/win-unpacked/`，复制时必须保留整个目录。安装包内包含 Python 后台和 Electron，使用者不需安装开发环境；可选本地语音的大型依赖在启用时下载。

**Live2D 实验工具另行启用：** `setup.cmd -WithLive2D` 或 `live2d.cmd -Mode doctor`。它会把 PSD2Live 的便携版（含 Java）和拆层依赖放进本项目。用法见 [Live2D 工具说明](tools/avatar_pipeline/README.md)。生成图片仍需自己的图片 API 密钥；绑定需校准图层/关节配置，不能把实验脚本当作任意图片自动绑定服务。新版角色卡使用视频播放，旧场景保留原有2.5D渲染器。

固定版本、校验下载、换路径重建、离线范围、支持平台和验证方式见 [环境与打包说明](docs/PORTABLE.md)。macOS/Linux 仍采用后文的手动安装方式，并须在目标系统构建；本次一键环境入口仅支持 Windows x64。

**Git 仓库不包含本机生成的角色、安装包或已配置密钥。** 全新克隆后需要自行配置图片服务、生成场景，或导入已有项目包。请勿直接照搬本文提到的本机验收路径。

## 0.2.1 图片连接修复

图片重绘服务增加“跟随系统代理 / 直连 / 手动代理”。Windows 默认读取系统代理；macOS/Linux 使用代理环境变量。手动模式可填写 `http://127.0.0.1:7890` 等 HTTP 代理地址。这是请求代理配置，不会启动、关闭或修改 VPN。全局 VPN 隧道由操作系统路由控制，软件只能确认是否使用显式代理。

独立桌面客户端：Electron 窗口 + 内置 Chromium 画面/音频 + Python/FastAPI 后台 + SQLite。发布包包含 Python 运行时和依赖，目标电脑无需安装 Python、Node 或另开浏览器。HTML/CSS/JavaScript 仅作为客户端内部渲染技术。

## 开发启动与构建

执行 `start.cmd` 或 `start.ps1` 启动客户端；它会自动准备环境并复用项目的 `data/`。

Windows 一键环境：

```powershell
.\setup.cmd
.\start.cmd
```

Windows 打包：

```powershell
.\build.cmd
# 或分步执行
.\.venv\Scripts\python.exe scripts/build_backend.py
npm run dist:win
```

macOS / Linux：

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-build.txt
npm ci
npm start
# 在目标系统和CPU架构上构建后台，再打包
.venv/bin/python scripts/build_backend.py
npm run dist:mac    # macOS ZIP / .app
# 或 npm run dist:linux  # Linux AppImage
```

不要把 Windows 的 `build/backend/` 拿到 macOS/Linux 打包。Python、Pillow 等包含平台相关二进制，必须在对应 OS/CPU 上重建。`requirements-build.lock.txt` 是 Windows x64 的带哈希构建锁；macOS/Linux 使用 `requirements-build.txt` 在目标平台解析构建工具。`.github/workflows/desktop.yml` 提供可手动触发的三个系统构建流程，Windows 走同一套一键脚本。macOS Intel/Apple Silicon 需分别构建，其他平台结果不等于本机实测。

如果宿主设置了 `ELECTRON_RUN_AS_NODE`，启动 Electron 前需清除；`start.ps1` 已处理。可通过 `YINGBO_PYTHON` 指定开发时的 Python，通过 `JIBO_DATA_DIR` 指定数据目录（兼容 `YINGBO_DATA_DIR`），通过 `YINGBO_PORT` 指定首选端口。

## 跨平台设计

| 项目 | 处理方式 |
|---|---|
| 界面、音频、字幕和嘴型 | 内置Chromium；角色卡按语音状态切换整段视频，嘴部活动来自视频；旧场景由音频驱动 |
| Python 后台 | PyInstaller 按目标平台打包，用户不用配置环境 |
| 数据 | 与程序资源分离；普通安装用用户目录，便携版用 EXE 旁的 JiboData（兼容YingboData） |
| 启动和关闭 | 自动启动后台、健康检查；关闭客户端结束后台；端口冲突时自动分配 |
| Windows 语音 | 使用目标机器已安装的中文 SAPI 音色，缺少时明确报错 |
| macOS/Linux 语音 | 默认使用兼容 `/audio/speech` 的本地或云端服务 |
| 迁移 | 项目包带走形象、参考图、商品、规则和答谢模板；服务密钥需重新填写 |

没有把 Windows 系统音色当作跨平台能力。CosyVoice 等模型可以通过兼容服务接入，当前没有内置大型模型和 PyTorch。直接复制数据目录到其他系统会保留旧音色配置，建议用项目导入导出并重新设置 TTS。

## 第一次使用

1. 接入设置填写图片服务的基础地址、模型、密钥和代理，先测试连接。Windows 默认可使用已安装的中文系统音色，其他系统需配置兼容 TTS。
2. 形象工坊上传参考图，点击生成完整场景；会产生4次图片服务调用费用，不自动重试。也可导入已有项目包。
3. 载入场景预览，检查表情、绑定和衣料范围，确认后用于直播。生成模型前不能开始彩排，不再使用独立嘴部替代。
4. 商品知识库填写真实参数、价格、FAQ 和分段讲解稿；示例商品仅供验证。修改稿件或音色后重新开始彩排。
5. 直播工作台选择角色场景和商品，开始彩排，模拟商品提问、屏蔽语句和礼物，观察处理记录和语音。

场景生成会标准化角色、生成表情及独立背景，再去绿幕并绑定。它不是自动拆层绑定的 Live2D；衣料使用遮罩内纹理流动，外轮廓固定。单纯上传图片不会自动变成模型。

## 项目迁移

点击“导出迁移项目”，通过原生保存对话框导出 ZIP。在另一客户端点击“导入项目”。导入会替换形象、商品和规则，并在当前数据目录的 `backups/` 中先保存旧项目。

项目包不含 API 密钥、音色配置或缓存；当前机器的服务密钥不会被导入覆盖。数据目录中的 SQLite 含本机密钥，当前未使用系统密钥链加密。复制完整目录前先退出客户端，不要只复制正在写入的 SQLite 主文件。

## 透明播出窗口与 OBS

“打开播出窗口”打开独立透明桌面窗口，顶部悬停条可拖动，右上角关闭，也可通过“播出”菜单关闭。

OBS 推荐使用客户端“复制地址”的浏览器源，宽1080、高1920。这样不依赖各操作系统的透明窗口捕获。地址含本机访问凭据，请勿公开分享。客户端内置服务只监听本机，不对局域网开放。

OBS 启用“通过 OBS 控制音频”。播出窗口和 OBS 比工作台预览优先；不要同时启用多个播出画面。关闭后预览约8秒恢复接管；切换时当前片段从头播放。

默认首选8765端口，冲突时选择空闲端口。重启后以客户端复制的新地址为准。程序只控制本地节目，不会自行启动抖音直播。

## 事件接入

接入设置显示实际地址。`POST /api/events`，请求头为 `Authorization: Bearer <事件接入密钥>`。

```json
{"event_id":"comment-001","kind":"comment","username":"小林","text":"多久发货？"}
```

```json
{"event_id":"gift-001","kind":"gift","username":"小林","gift":"鲜花","count":3}
```

重复编号不会再次处理；礼物连击应由采集端合并。抖音采集器暂未包含。事件密钥与桌面内部访问凭据不同。

## Git 提交范围

保留源码、测试、内置示例资源、npm锁文件、Python依赖、版本清单、构建脚本和说明。`.gitignore` 排除 `.runtime/`、`.venv/`、`node_modules/`、`build/`、`release/`、`data/`、`YingboData/`、`JiboData/`、测试输出、SQLite、日志、环境密钥文件、证书以及 `.vs/` 等 IDE 缓存。不要把 `.venv` 提交到 Git：虚拟环境带有绝对路径且不能跨平台搬运，另一台机器应由脚本按锁文件重建。

服务密钥保存在用户数据目录的 SQLite 中；当前未使用系统密钥链加密，请勿上传数据库或整份用户数据。安装包应单独通过发行渠道提供，不加入源代码提交。

默认规则与证据检查不能保证识别全部不适宜内容或模型错误。正式播出前需用真实商品、实际服务商和真实平台接口做验收。目前尚不包含完整 Live2D 绑定、账号体系、自动更新或长期无人值守保障。
